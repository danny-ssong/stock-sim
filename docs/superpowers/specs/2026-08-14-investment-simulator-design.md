## 1. 개요

한국 투자자가 **"목표 금액을 모으려면 매달 얼마씩, 어느 계좌에, 무엇에 투자해야 하는가"** 에 답하는 웹 시뮬레이터.

기존 복리 계산기와의 차이는 세 가지다.

1. **한국 세제를 실제로 계산한다.** 해외직투 양도소득세, 국내상장 해외ETF 배당소득세, ISA 분리과세를 계좌별로 다르게 적용한다.
2. **과거 실제 데이터로 검증한다.** 1995년부터의 일별 종가·환율·금리를 사용한다. 상장 이전 구간은 지수 기반 합성값을 쓰되 **합성임을 명시**한다.
3. **낙관적 가정을 강요하지 않는다.** 레버리지 ETF의 변동성 끌림, 최대낙폭, 회복 소요기간을 정면으로 보여준다.

### 설계 원칙

| 원칙 | 의미 |
|---|---|
| **정직성 우선** | 합성 데이터, 추정치, 법령 불확실성을 숨기지 않고 UI에 표시한다 |
| **단일 엔진** | 세 개 탭이 같은 계산 엔진을 재사용한다. 계산 로직 분기는 입력에서만 발생한다 |
| **순수 함수** | `lib/` 전체가 React 비의존 순수 함수. 테스트 가능성이 신뢰성의 근거다 |
| **확장 포인트 개방** | 계좌 종류, 상품, 세법 상수는 인터페이스/테이블로 분리해 추가 시 기존 코드를 건드리지 않는다 |

## 3. 범위

### In scope (v1)

- 지수 노출 7종 × 계좌 3종 시뮬레이션
- 월 적립식 / 거치식 / 혼합
- **연도별 납입액·근로소득 편집** — 상승률 자동 증가 + 특정 연도 직접 수정(anchor) 시 이후 재계산
- **국내상장 vs 해외직투 세금 비교** — 누진 폭발 경고와 분할 매도 안내
- 계좌별 세금 계산 (해외직투 / 국내상장 해외ETF / ISA)
- **금융소득종합과세 누진 계산** — 현재 연봉 입력 + 연봉상승률로 연도별 근로소득을 추정해 **매 연도** 판정
- **해외직투 연간 기본공제 소진 전략** — 매년 250만원까지 실현 후 재매수
- 계좌 간 이전(직투 → ISA) 이벤트와 손익분기 분석
- 1995년~현재 과거 백테스트 (미국 상장 상품은 합성 구간 포함)
- USD/KRW 실제 환율 반영(1970~), 원화/달러 표시 토글
- **환율 가정 선택** — 고정 / 과거 경로 / 연 추세 (§5.6)
- 외식물가지수 기반 품목 가격 환산 (국밥, 김밥 등)
- URL 기반 시나리오 공유

### Out of scope (v1)

| 제외 항목 | 사유 |
|---|---|
| 연금저축 / IRP | 사용자 결정. `TaxStrategy` 인터페이스로 v2 확장 가능하게 설계 |
| 환헤지 상품 | 사용자 결정. 환노출 기준으로만 계산 |
| **국내 상장 상품의 상장 이전 백필** | 수익 공식을 실측으로 확정하지 못함 (§4.6). 상장일 이후만 제공 |
| **SCHD의 2011-10 이전 구간** | 기초지수가 공개 소스에 없음 |
| 계정 / DB / 로그인 | URL 쿼리스트링으로 충분. 개인 금융정보를 서버에 두지 않는다 |
| 개별 주식 (AAPL 등) | 지수 ETF 7종으로 한정 |
| 정밀 소득공제 (부양가족·연금·보험료) | 근로소득공제 + 기본공제만 적용한 **근사 과세표준**을 쓴다. 과세표준 직접 입력 옵션으로 우회 가능 |

```typescript
  displayName: string;
```

> #### ⛔ 국내 상장 상품은 합성 백필을 하지 않는다

### 4.6 ⚠️ 레버리지 모델이 두 종류인 이유

**이 문서에서 가장 중요한 모델링 결정이다.**

같은 "나스닥100 2배 환노출"이라도 미국 상장 QLD와 국내 상장 TIGER 레버리지(합성)는 **수익 구조가 다르다.**

```
QLD 원화 환산 일별 수익률
  = (1 + 2 × r_index − cost) × (1 + r_fx) − 1
    → 지수에만 2배, 환율은 1배

TIGER 미국나스닥100레버리지(합성) 일별 수익률
  = 2 × (r_index + r_fx) − cost
    → 환율에도 2배
```

원/달러가 오르는 구간에서는 국내 상품이 유리하고, 내리는 구간에서는 손실이 2배로 확대된다.

#### ⚠️ 실측 검증 결과 — 공식을 확정하지 못했다

TIGER 418660 실제 데이터(2022-02-22 ~ 2026-08-13, 1,038 거래일)로 두 모델을 검증했으나 **결론이 나지 않았다.**

```
실제 TIGER 418660 누적          +352.1%

lag=0   모델US −17.3%p   모델KR +34.1%p   → US 우세
lag=2   모델US −32.4%p   모델KR +12.3%p   → KR 우세
```

한국장 마감과 미국장 마감의 시차(lag) 가정에 따라 **승자가 뒤집힌다.** 두 모델 모두 오차가 12~108%p로 크다.

**확실한 것은 하나뿐이다.** 같은 기간 국내 상품이 QLD 원화환산보다 크게 앞섰다.

| | 4.12년 누적 |
|---|---|
| TIGER 418660 (국내 환노출) | **+352.1%** |
| QLD 원화환산 | +253.4% |
| QLD (달러) | +198.0% |
| USD/KRW | +18.6% |
| 나스닥100 지수 | +116.9% |

차이는 실재하나 그 원인이 환율 배율인지, 스왑 비용·기초지수 차이·NAV 산정 방식인지 **데이터로 특정하지 못했다.**

#### 그래서 내린 결정

1. **국내 상장 상품은 합성 백필을 하지 않는다** (§4.3). 공식을 모르면 과거를 만들어내지 않는다.
2. `LeverageModel` 타입 분기는 **유지**한다. 투자설명서로 공식이 확정되면 즉시 반영할 수 있는 자리를 남겨둔다.
3. 투자설명서 확인을 구현 전 필수 항목으로 둔다 (§14).

### 배율별로 차이의 크기가 다르다

| 배율 | 국내 vs 해외 원화 수익률 차이 | 처리 |
|---|---|---|
| **1배** | 사실상 동일. 추적오차와 총보수 차이(연 0.05~0.15%p)만 발생 | 같은 공식, 보수만 다르게 |
| **2배 이상** | **구조적으로 다름.** 환율에 배율이 곱해지느냐가 갈린다 | `LeverageModel` 분기 필수 |

1배에서 `(1 + r_idx)(1 + r_fx)` 와 `1 + r_idx + r_fx` 의 차이는 교차항 `r_idx × r_fx` 뿐이고, 일별 수익률에서 이 값은 무시할 수준이다. 배율이 붙으면 교차항이 증폭되어 누적 차이가 커진다.

**사용자는 국내/해외를 모두 선택할 수 있고**, 같은 노출을 두 계좌로 담아 비교하는 것이 탭 3의 주요 사용 사례다.

## 5. 계산 엔진

### 5.0 입력 타입

```typescript
type SimulationInput = {
  initialAmount: number;
  years: number;

  /** 월 납입액 — 연도별 anchor 스케줄 (§5.4) */
  contribution: AnchoredSchedule;
  /** 연 근로소득 — 동일한 anchor 스케줄. 종합과세 계산에 사용 (§6.4) */
  employmentIncome: AnchoredSchedule;
  /** 과세표준 직접 입력 (근로소득공제 계산을 건너뜀) */
  taxBaseOverride?: number;

  allocations: Array<{
    accountId: AccountId;
    exposure: IndexExposure;
    weight: number;                  // 합계 1.0
  }>;

  returnSource: ReturnSource;
  fxAssumption: FxAssumption;                 // 탭1 기본 fixed / 탭2 기본 historicalPath
  realizationStrategy: RealizationStrategy;   // 기본 annualDeductionHarvest
  transferEvents: TransferEvent[];

  displayCurrency: 'KRW' | 'USD';
};
```

### 5.1 파이프라인

```
SimulationInput
   │
   ├─[1] resolveProducts()      계좌 × 노출 → 상품 확정 (불가 조합 거부)
   ├─[2] buildPriceSeries()     일별 KRW 환산 가격 시계열 (합성·레버리지 포함)
   ├─[3] sampleMonthly()        일별 → 월별 매수 시점 샘플링
   ├─[4] buildLedger()          월별 원장 생성          ← 핵심
   ├─[5] applyAccountTax()      계좌별 세금 (TaxStrategy)
   ├─[6] applyComprehensiveTax() 연 단위 금융소득종합과세 (계좌 횡단)
   └─[7] summarize()            요약 + 물가 환산
   │
SimulationResult
```

### 5.1.1 일별 / 월별 경계

**두 해상도를 쓰는 이유가 있다.**

| 단계 | 해상도 | 근거 |
|---|---|---|
| 가격 시계열 · 합성 · 레버리지 | **일별** | 레버리지는 일별 복리로 정의된다. 월별로 계산하면 변동성 끌림이 사라져 결과가 근본적으로 틀린다 |
| 원장 · 납입 · 세금 | **월별** | 적립은 월 단위 행위다. 일별 원장은 30배 무겁기만 하고 정확도를 더하지 않는다 |

경로 반복(tile)도 **일별 가격 시계열 레벨**에서 수행한다. 월별 샘플링은 그 이후 단계다.

**매수 시점:** **매월 1일, 월 1회**로 고정한다. 1일이 휴장일이면 **다음 거래일 종가**를 사용한다. 실제 자동이체 관행과 일치하고, 매수 시점을 변수로 만들지 않는다.

**배당 처리:** 전부 **재투자**를 가정한다. 미국 ETF 배당은 원천징수 15% 차감 후 재투자, 국내 상장 분배금은 계좌별 과세 규칙 적용 후 재투자. 재투자 단가는 배당락일 다음 거래일 종가다.

### 5.2 월별 원장 (Ledger) — 단일 진실 소스

세 탭이 공유하는 자료구조. 세금·차트·요약이 전부 여기서 파생된다.

### 5.3 수익률 소스

```typescript
type ReturnSource =
```

**경로 반복(tile) 규칙** — 사용자 결정에 따라 단순 반복 방식을 채택한다.

참조 구간이 시뮬 기간보다 짧으면 **일별 수익률 배열을 처음부터 다시 순환**시킨다. 3년 구간으로 10년을 시뮬하면 3.33회 반복된다. 반복은 **일별 해상도**에서 일어난다 (§5.1.1).

```

시뮬: [r0, r1, ..., r755, r0, r1, ..., r755, r0, ...]  (10년 = 약 2,520 거래일)
```

UI에 `이 시뮬레이션은 2023-08~2026-08 구간(3년)을 3.3회 반복 적용합니다`를 명시한다.

#### 참조 구간이 상장일 이전이면 경로 재생을 쓸 수 없다

국내 상장 상품은 합성 백필을 하지 않으므로(§4.3), 참조 구간에 상장 이전이 포함되면 재생할 경로 자체가 없다.

```typescript
type ReturnSourceResolution =
  | { ok: true; source: ReturnSource }
  | { ok: false; reason: 'BEFORE_LISTING'; listedAt: string; suggestion: ReturnSource };
```

**동작:** 경로 재생이 불가능하면 **CAGR 모드로 자동 전환**하고 안내한다. 조용히 다른 구간으로 바꾸거나 합성하지 않는다.

```
⚠️ TIGER 미국나스닥100레버리지는 2022-02-22 상장입니다.
   2011~2026 구간의 실제 경로가 없어 CAGR 모드로 전환했습니다.
   [상장 후 구간(2022~2026)으로 참조 변경]  [CAGR 직접 입력]
```

이 때문에 **국내 상장 상품의 장기 미래 시뮬은 사실상 CAGR 모드가 기본**이 된다. 특히 TIGER 레버리지는 실제 이력이 4년뿐이라 경로 재생의 의미가 적다.

**CAGR 직선 모드**에서는 전 구간에 동일한 일별 수익률을 적용한다.

```
r_daily = (1 + annualRate)^(1/252) − 1
```

두 모드는 같은 함수 시그니처를 쓴다 — 직선은 "모든 원소가 같은 배열"의 특수 케이스일 뿐이다.

```typescript
function buildLedger(input: SimulationInput, dailyReturns: Float32Array): Ledger;
```

### 5.4 Anchor 스케줄 — 납입액과 근로소득의 연도별 관리

납입액과 근로소득은 **같은 문제**를 갖는다. 기본은 상승률로 자동 증가하되, 특정 해에 값이 점프할 수 있어야 한다 (이직, 성과급, 대출 상환 완료 등). 그리고 그 점프 이후로는 **새 값을 기준으로** 다시 상승률이 붙어야 한다.

두 곳에 같은 구조가 필요하므로 **하나의 재사용 가능한 스케줄 타입**으로 뽑는다.

```typescript
type AnchoredSchedule = {
  /** 0년차 기준값 */
  base: number;
  /** 연 상승률 */
  growthRate: number;
  /** 연차 → 그 해의 값. 이 연도가 새 기준점이 된다 */
  anchors: Record<number, number>;
};

/** 가장 가까운 이전 anchor를 찾아 거기서부터 상승률을 적용한다 */
function resolveAtYear(schedule: AnchoredSchedule, yearIndex: number): number {
  const anchorYears = Object.keys(schedule.anchors)
    .map(Number)
    .filter((y) => y <= yearIndex);

  const anchorYear = anchorYears.length > 0 ? Math.max(...anchorYears) : 0;
  const anchorValue = schedule.anchors[anchorYear] ?? schedule.base;

  return anchorValue * (1 + schedule.growthRate) ** (yearIndex - anchorYear);
}
```

**동작 예시** — 월 500만원 시작, 연 5% 상승, 4년차에 1,000만원으로 수정

| 연차 | 값 | 계산 |
|---|---|---|
| 0 | 500만 | base |
| 1 | 525만 | 500 × 1.05 |
| 2 | 551만 | 500 × 1.05² |
| 3 | 579만 | 500 × 1.05³ |
| **4** | **1,000만** | **anchor (사용자 입력)** |
| 5 | 1,050만 | 1,000 × 1.05 |
| 6 | 1,103만 | 1,000 × 1.05² |
| 7 | 1,158만 | 1,000 × 1.05³ |

4년차 수정이 **그 이후 전체를 다시 계산**시킨다. 이전 연도(0~3)는 영향받지 않는다.

anchor를 여러 개 둘 수 있고, 각각 다음 anchor가 나올 때까지 유효하다. anchor를 삭제하면 그 이전 anchor 기준으로 자동 복귀한다.

**증액 시점:** 매년 **1월**로 고정한다 (연말정산·연봉협상 주기와 일치). 월 단위 납입액은 그 해 내내 동일하다.

> 납입액과 근로소득에 같은 타입을 쓰지만 **상승률은 각각 따로 설정**한다. 연봉은 5% 오르는데 납입액은 10% 늘리는 계획이 자연스럽기 때문이다.

### 5.5 합성 시계열 생성

상품 상장일 이전 구간을 기초지수로 역산한다.

```
합성 일별 수익률 = mult × r_index − ((mult − 1) × rate(t) + spread) / 252
```

- 기초지수: NASDAQ-100 TR(=PR + 배당 레이어), S&P 500 TR
- 기준금리: **Yahoo `^IRX`(13주 국채 수익률, 1970~).** 연율 퍼센트 단위로 오므로
  100으로 나눠 소수 비율로 바꿔 쓴다 (예: 3.70 → 0.037)
- 스프레드: **고정값이 아니라 종목별 실측 적합값**(`backfillSpread`). 운용보수·
  배당수익률·추적오차를 모두 흡수한 잔차 성분이며, 배당이 보수를 넘어서면
  음수가 된다 (배율 1 상품에서 흔함)

**금리 시계열을 포함하는 이유:** 1995~2026년 미국 기준금리는 0%~6.5%를 오갔다. 3배 레버리지의 차입비용은 연 0%~13%까지 변동하므로 30년 시뮬에서 고정값으로 두면 결과가 크게 왜곡된다.

**합성 정확도 검증 (골든 테스트):** QLD/TQQQ/SSO/SPXL의 *실제 상장 이후* 구간에 동일한 합성 공식을 적용해 실제 종가와 비교한다. 판정 기준은 두 가지다.

- **표본 외(out-of-sample) CAGR 오차가 3%를 초과하면 CI 실패**
- **변동성 비율이 0.9~1.1을 벗어나면 CI 실패**

**왜 표본 외인가.** 스프레드를 이분탐색으로 역산하는 알고리즘(`calibrateSpread`)은 정의상 전체 구간의 CAGR 오차를 0으로 만든다 — 자유 파라미터 하나로 목표값 하나를 맞추는 것이므로, 표본 내 오차는 애초에 검증력이 없다. 진짜 시험은 겹침 구간을 반으로 나눠 전반부로 스프레드를 적합하고 그 상수를 후반부(표본 외, 금리 체제가 달라질 수 있는 구간)에 적용했을 때도 통하는가다. 이 구조 덕분에 고정 드래그 모델(금리 미반영)과 금리 연동 모델의 차이가 뚜렷하게 드러난다 — 금리 체제가 바뀌는 구간에서 고정 드래그 모델의 표본 외 오차는 금리 연동 모델의 5배 이상으로 벌어진다(`calibrate.test.ts`).

#### 미래 시뮬레이션의 환율 가정 — 경로 재생을 기본값으로 두지 않는다

주가와 환율은 성격이 다르다. **주가는 장기 우상향 경향이 있지만 환율은 등락을 반복한다.** 과거 환율 경로를 미래에 그대로 재생하면 "원화가 계속 약세로 간다"는 강한 방향성 가정이 숨어 들어간다.

예를 들어 2022~2026 구간을 참조하면 환율이 **+18.6%** 오른 경로가 그대로 미래에 복사된다. 15년으로 늘리면 이 가정만으로 수익률이 크게 부풀려진다.

```typescript
type FxAssumption =
  /** 고정 — 오늘 환율이 유지된다고 가정 */
  | { type: 'fixed'; rate: number }
  /** 과거 경로 재생 — 실제로 그랬던 구간을 재현 */
  | { type: 'historicalPath' }
  /** 연 X% 추세 — 사용자가 방향성을 명시적으로 지정 */
  | { type: 'drift'; annualRate: number };
```

**탭별 기본값**

| 탭 | 기본값 | 근거 |
|---|---|---|
| 탭 1 · 미래 설계 | **`fixed`** (오늘 환율) | 미래 환율 방향을 모르면 중립이 정직하다 |
| 탭 2 · 과거 백테스트 | **`historicalPath`** | 실제로 그랬던 일을 재현하는 것이 목적이다 |
| 탭 3 · 비교 | 탭 1과 동일 | |

> 이 가정은 **국내 상장 상품만의 문제가 아니다.** 미국 상장 ETF도 원화로 환산하는 순간 같은 문제를 안는다. 따라서 `FxAssumption`은 전 상품에 공통 적용한다.

**UI:** 환율 가정을 결과 카드에 항상 노출한다. `환율 1,548원 고정 가정` / `2011~2026 실제 환율 경로 적용`처럼 어떤 가정이 쓰였는지 숨기지 않는다.

### 5.7 목표금액 역산 (Goal Seek)

**입력:** 목표금액(세후 명목), 기간, 배분, 납입 스케줄의 *형태*
**출력:** 필요 월납입액 수준

#### ⚠️ anchor가 있으면 base만 조정해서는 안 된다

`base`만 이분탐색으로 움직이면 **anchor가 걸린 연도 이후는 전혀 변하지 않는다.** 4년차에 1,000만원 anchor가 있으면 5~15년차 납입액이 고정되어, base를 아무리 올려도 최종 금액이 거의 늘지 않는다. 단조성이 깨지고 수렴하지 않는다.

**해결: 스케줄 전체를 비례 스케일링한다.**

```typescript
function scaleSchedule(schedule: AnchoredSchedule, factor: number): AnchoredSchedule {
  return {
    base: schedule.base * factor,
    growthRate: schedule.growthRate,          // 형태는 유지
    anchors: mapValues(schedule.anchors, (v) => v * factor),
  };
}
```

사용자가 설계한 **납입 패턴의 형태(상승률·점프 시점·상대적 크기)는 보존**하면서 전체 수준만 찾는다. "4년차에 두 배로 늘리는 계획"은 그대로 두고 "그 계획 전체를 1.3배 해야 목표에 닿는다"를 알려주는 것이다.

결과 표시도 이에 맞춘다.

```
목표 3억 달성하려면 현재 계획의 1.28배가 필요합니다

  1년차   500만 → 640만
  4년차 1,000만 → 1,280만  📌
 15년차 1,710만 → 2,189만
```

#### 이분탐색

스케일 배수가 커지면 최종 세후금액도 증가하는 단조 관계이므로 **이분탐색**으로 푼다.

```
lo = 0, hi = 2.0
hi에서도 목표 미달이면 hi를 2배씩 늘린다 (최대 1000배)

반복 60회 또는 |결과 − 목표| < 1원 까지:
  mid = (lo + hi) / 2
  결과 = simulate(scaleSchedule(schedule, mid)).finalAfterTax
  결과 < 목표 ? lo = mid : hi = mid
```

ISA 납입한도와 250만원 공제 때문에 국소적으로 계단이 생기지만, 실질적 단조성은 유지되어 수렴한다.

**성능:** 가격 시계열(일별)은 월납입액과 무관하므로 **이분탐색 루프 밖에서 한 번만 계산**한다. 루프 안에서 반복되는 것은 `개월수 × 계좌수` 원장 생성과 세금 계산뿐이라, 60회 반복도 브라우저에서 수 ms 안에 끝난다.

**도달 불가능한 목표:** `hi` 상한에서도 목표에 미달하면 수렴을 시도하지 않고 `{ reachable: false, maxAchievable }` 을 반환한다. UI는 "이 조건으로는 달성 불가 — 기간을 늘리거나 목표를 낮추세요"와 함께 달성 가능한 최대치를 보여준다.

**역방향(월납입액 → 목표금액)** 은 단순 순방향 계산이다. UI에서 두 필드는 양방향으로 연결된다.

### 5.8 계좌 간 이전 (직투 → ISA)

```typescript
type TransferEvent = {
  atMonth: number;
  from: 'DIRECT_US';
  to: 'ISA';
  amount: number | 'all';
};
```

**처리 순서:**

1. 직투 계좌에서 해당 금액만큼 매도 → **양도차익 실현**
2. 해당 연도 양도소득세 계산: `(실현이익 − 250만원 기본공제) × 22%`
3. 세후 현금이 ISA 납입 원금이 됨
4. ISA 연 2,000만원 한도 초과분은 **다음 해로 자동 이월** (초과 납입 불가)
5. ISA에서 대응 국내상장 상품 재매수 (매핑 불가 시 이전 자체를 거부)

**손익분기 분석:** 이전한 경우와 하지 않은 경우를 동일 경로로 병렬 시뮬하고, 세후 평가액이 역전되는 시점을 찾는다.

```
직투 유지          vs   3년차 전량매도 → ISA 이전
─────────────────────────────────────────────
즉시 세금    0원          55만원 (양도세)
10년 뒤 세후 4.21억        4.38억
                          → 6년차부터 역전, 최종 +1,700만원 유리
```

## 6. 세금 엔진

### 6.1 전략 인터페이스

계좌를 추가할 때 기존 코드를 수정하지 않도록 인터페이스로 분리한다. v2에서 연금저축/IRP를 붙일 때 이 인터페이스만 구현하면 된다.

```typescript
interface TaxStrategy {
  readonly accountId: AccountId;

  /** 해당 연도 납입 가능 한도 (null = 무제한) */
  contributionLimit(year: number, history: ContributionHistory): number | null;

  /** 이 계좌에 해당 노출을 담을 수 있는가 */
  canHold(exposure: IndexExposure): ProductResolution;

  /** 보유 중 매년 발생하는 세금 (배당소득세 등) */
  annualTax(yearLedger: YearLedger, ctx: TaxContext): TaxBreakdown;

  /** 최종 매도 시 세금 (양도소득세, ISA 정산 등) */
  exitTax(ledger: Ledger, ctx: TaxContext): TaxBreakdown;
}
```

### 6.2 계좌별 규칙

**DIRECT_US — 해외주식 직접투자**

- 매매차익: 양도소득세 22% (지방소득세 포함), **연 250만원 기본공제**
- 분류과세 → 금융소득종합과세 합산 대상 아님
- 배당: 미국 원천징수 15% (한미 조세조약). 배당소득은 종합과세 대상 (§6.4)
- 손익통산: 같은 연도 내 해외주식 간 통산 가능
- **매도 시점에만 과세** → 미실현 상태로 오래 끌수록 과세이연 효과

**DOMESTIC_ETF — 국내상장 해외ETF 일반계좌**

- 매매차익과 분배금 모두 **배당소득으로 과세, 15.4% 원천징수**
- 매매차익 과세표준 = min(실제 매매차익, 과표기준가 증가분)
- **금융소득종합과세 합산 대상** → 연 2,000만원 초과 시 근로소득과 합산 누진 (§6.4)
- 손익통산 불가 — 손실 난 종목이 있어도 이익 난 종목에 그대로 과세된다 (툴팁 명시)

**ISA — 중개형**

- 납입한도: **연 2,000만원, 총 1억원**. 미사용분은 다음 해로 이월
- 의무보유: **3년**. 미충족 시 일반계좌와 동일 과세로 소급
- 정산: 계좌 내 **모든 손익을 통산**한 순소득 기준
  - 순소득 200만원까지 **비과세**
  - 초과분 **9.9% 분리과세** (금융소득종합과세 제외)
- 국내 상장 상품만 편입 가능

> 서민형 ISA(비과세 400만원)는 소득 요건 확인이 필요해 **v1에서는 일반형만** 지원한다.

### 6.3 해외직투 — 연간 기본공제 소진 전략

해외주식 양도소득 기본공제 250만원은 **연 단위로 초기화되고 이월되지 않는다.** 쓰지 않으면 소멸한다.

그래서 실무에서 널리 쓰이는 절세 방법이 있다. **매년 250만원어치 이익만큼 매도한 뒤 즉시 재매수**하는 것이다. 세금은 0원이지만 취득원가가 그만큼 올라가서(step-up), 최종 매도 시 과세 대상 이익이 줄어든다.

```typescript
type RealizationStrategy =
  /** 기본값 — 매년 기본공제 한도까지 실현 후 재매수 */
  | { type: 'annualDeductionHarvest' }
  /** 비교용 — 최종 시점에 전량 매도 */
  | { type: 'holdUntilExit' };
```

**연간 처리 (매년 12월 기준)**

```
실현액_t   = min(기본공제 250만원, 미실현이익_t)
세금_t     = 0                       // 공제 범위 내
취득원가   += 실현액_t                // step-up
```

**최종 매도 시**

```
잔여이익  = 평가액 − 조정된 취득원가
최종세금  = max(0, 잔여이익 − 250만원) × 22%
```

**효과 예시:** 30년 보유 시 250만 × 30 = **7,500만원의 이익**이 비과세로 처리된다.

```
비과세로 넘어간 이익   7,500만원
실제 절세액           7,500만원 × 22% = 1,650만원
```

> 두 숫자를 혼동하지 않도록 UI에서도 분리해 표시한다. 사용자가 보고 싶은 것은 **절세액 1,650만원**이지 비과세 이익 7,500만원이 아니다.

**가정과 한계 (툴팁에 명시)**

- 매도-재매수 사이의 가격 변동은 없다고 가정한다 (당일 재매수)
- 거래수수료와 매수·매도 호가 스프레드는 계산하지 않는다
- 미실현이익이 250만원에 못 미치면 그만큼만 실현한다
- 미실현손실 상태면 실현하지 않는다

UI에서 **토글**로 제공하고 기본값은 ON이다. OFF와 비교하면 절세 효과가 얼마인지 바로 보인다.

### 6.4 금융소득종합과세 엔진

**연 근로소득 입력이 필요한 이유:** 금융소득이 2,000만원을 넘으면 초과분이 근로소득과 합산되어 누진세율을 맞는다. 근로소득이 얼마인지 모르면 세율을 알 수 없다.

#### 금융소득은 매년 발생한다 — 마지막 해만 계산하면 틀린다

종합과세 판정은 **연 단위**다. 그리고 금융소득은 시점에 따라 성격이 다르다.

| 시점 | 발생 항목 | 규모 |
|---|---|---|
| **매년** | 국내ETF 분배금, 해외주식 배당 | 소액 — 대개 2,000만원 미만이라 미발동 |
| **매도 연도** | 국내ETF 매매차익 **전액**이 그 해 배당소득으로 계상 | 거액 — 발동 가능성 높음 |
| **이전 연도** | 직투 → ISA 이전 시 실현 손익 | 양도차익은 분류과세라 종합과세 무관 |

따라서 **매 연도마다 판정**해야 하고, 그러려면 **매년의 근로소득**이 필요하다.

#### 연도별 근로소득 추정

사용자가 아는 값은 **현재 연봉**이지 15년 뒤 연봉이 아니다. §5.4의 `AnchoredSchedule`을 그대로 사용해 매년 추정하고, 특정 해를 수정하면 그 이후가 재계산된다.

```
t년차 근로소득 = resolveAtYear(input.employmentIncome, t)
```

**매도 시점의 연봉이 최종 세율을 좌우한다.** 금융소득이 몰리는 해의 세율 구간이 근로소득 위에 얹히기 때문이다. 따라서 그 값을 사용자가 확인하고 고칠 수 있어야 한다.

```
현재 연봉  [ 6,000만원 ]   연봉 상승률 [ 5% ]
  ↓
15년차(매도 시점) 예상 연봉   1억 2,470만원   [직접 수정]
```

#### ⚠️ 한 해에 몰아 팔면 세율이 폭발한다 — 국내상장의 구조적 약점

국내상장 ETF의 매매차익은 **매도한 해에 전액이 배당소득으로 계상**된다. 30년을 모아 한 번에 팔면 그 해 금융소득이 수억이 되어 최고 구간에 들어간다.

**해외직투의 22%는 정액이지만 국내상장의 15.4%는 하한선일 뿐이다.** 금액이 커지면 역전된다.

#### 계산 방식과 표시 방식

세액은 **실제 누진세율로 정확히 계산**한다 (근사치로 대충 높게 잡지 않는다). 다만 결과에는 **최고세율 도달 여부와 최악 시나리오를 함께 표시**해 위험을 숨기지 않는다.

```typescript
type DomesticSaleTaxResult = {
  effectiveRate: number;        // 실제 누진 계산 결과
  topBracketReached: number;    // 도달한 최고 구간 세율 (예: 0.45)
  worstCaseTax: number;         // 전액이 최고구간이라 가정했을 때 (49.5%)
  splitSaleSaving: number;      // 5년 분할 매도 시 절감 추정액
};
```

#### 결과 화면 — 국내상장 vs 해외직투 세금 비교

같은 수익에서 세금이 얼마나 갈리는지 나란히 보여준다. 이것이 **탭 3의 핵심 인사이트**다.

```
━━ 국내상장 ETF · 15년차 일괄 매도 ━━━━━━━━━━━
  매매차익                    3.0억
  그 해 금융소득               3.0억
  도달 구간                   최고 45% (지방세 포함 49.5%)
  실효세율                    38.2%
  세금                       1.15억

  💡 5년에 걸쳐 나눠 팔면 약 2,600만원 절감 가능
     매년 6천만원씩 실현하면 24% 구간에 머무릅니다

━━ 해외직투 · 15년차 일괄 매도 ━━━━━━━━━━━━━
  양도차익                    3.0억
  분류과세 22% 고정            (누진 없음, 종합과세 합산 제외)
  세금                       6,545만원

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  같은 3억 수익, 세금 차이  4,955만원
  → 금액이 커질수록 해외직투가 유리해집니다
```

**핵심 메시지 3가지를 결과에 고정 노출한다:**

1. 국내상장은 **금액이 커지면 세율이 올라간다** (누진)
2. 해외직투는 **얼마를 벌든 22% 고정** (분류과세)
3. 국내상장을 택했다면 **여러 해에 나눠 파는 것**으로 완화할 수 있다

**손익분기 금액도 계산한다.** 15.4%와 22%가 역전되는 지점을 근로소득에 따라 산출해 "귀하의 연봉 6,000만원 기준, 매매차익 약 X원을 넘으면 해외직투가 유리합니다"로 표시한다.

v1은 **경고·실효세율·분할 매도 절감액 추정**까지 다룬다. 최적 매도 스케줄 탐색은 v2다.

#### 금융소득의 범위

| 소득 | 종합과세 대상 |
|---|---|
| 국내상장 해외ETF 매매차익·분배금 | ✅ |
| 해외주식 배당 | ✅ |
| 해외주식 **양도차익** | ❌ 분류과세 (별도 신고) |
| ISA 내 손익 | ❌ 분리과세 |

즉 ISA와 해외직투 양도차익은 아무리 커도 종합과세에 영향을 주지 않는다. **이것이 ISA의 숨은 장점**이며 탭 3에서 강조할 지점이다.

#### 근사 과세표준 산출

```
총급여 (사용자 입력)
  − 근로소득공제 (총급여 구간별, 한도 2,000만원)
  = 근로소득금액
  − 기본공제 150만원
  = 근사 과세표준
```

**근로소득공제 구간** — ✅ 국세청 공식 자료로 확인 완료 (공제 한도 **2,000만원**)

| 총급여 | 공제액 |
|---|---|
| 500만원 이하 | 총급여 × 70% |
| 500만원 초과 ~ 1,500만원 이하 | 350만 + (총급여 − 500만) × 40% |
| 1,500만원 초과 ~ 4,500만원 이하 | 750만 + (총급여 − 1,500만) × 15% |
| 4,500만원 초과 ~ 1억원 이하 | 1,200만 + (총급여 − 4,500만) × 5% |
| 1억원 초과 | 1,475만 + (총급여 − 1억) × 2% |

> 검증 사례 (국세청 공식): 총급여 3,380만원 → 공제 750만 + (3,380만 − 1,500만) × 15% = **1,032만원** → 근로소득금액 2,348만원. 이 값을 테스트 픽스처로 사용한다.
> 출처: https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?mi=6435&cntntsId=7871

부양가족·연금저축·보험료 공제는 계산하지 않는다. 실제 과세표준은 이보다 낮을 수 있으므로 **툴팁에 근사치임을 명시**하고, 정확한 값을 아는 사용자를 위해 **과세표준 직접 입력** 옵션을 둔다.

#### 비교과세

금융소득종합과세는 두 방식으로 계산한 뒤 **큰 쪽**을 적용한다. 분리과세보다 유리해지는 역전을 막는 장치다.

```
A = 종합소득세((근로 과세표준) + (금융소득 − 2,000만원)) + 2,000만원 × 14%
B = 종합소득세(근로 과세표준) + 금융소득 × 14%

산출세액 = max(A, B)
지방소득세 = 산출세액 × 10%
```

> 비교과세의 세율은 **지방소득세를 제외한 14%** 를 쓴다. 15.4%는 지방소득세를 포함한 원천징수율이므로 여기서 혼용하면 이중 계산이 된다.

> ✅ **2026-08-14 국세청 공식 자료로 확인 완료.** 2026년 귀속에도 8구간 6~45% 골격이 유지된다.

#### 구현 형태

종합과세는 **계좌 하나로 닫히지 않는다.** 여러 계좌의 금융소득을 합산해야 하므로 `TaxStrategy` 바깥의 **연 단위 후처리 단계**로 둔다.

```typescript
// lib/tax/comprehensive.ts
type ComprehensiveTaxInput = {
  year: number;
  yearIndex: number;                 // 0-based 경과 연차
  employmentIncome: number;          // 해당 연도 추정 총급여
  taxBaseOverride?: number;
  financialIncome: number;           // 계좌들에서 합산된 금융소득
  withheldTax: number;               // 이미 원천징수된 세액
};

type ComprehensiveTaxResult = {
  applicable: boolean;               // 2,000만원 초과 여부
  additionalTax: number;             // 원천징수분을 넘어 추가로 낼 세액
  effectiveRate: number;             // 금융소득 기준 실효세율
  method: 'A' | 'B';                 // 비교과세에서 채택된 쪽
};
```

**연도별 흐름** — 시뮬 전 기간의 **매 연도**에 대해 반복한다.

```
for (yearIndex of 0..years-1)
    근로소득_t = estimateEmploymentIncome(yearIndex)
              ↓
    각 계좌 TaxStrategy.annualTax()  →  금융소득·원천징수세액 산출
              ↓ 계좌 횡단 합산
    calculateComprehensiveTax(근로소득_t, 금융소득_t)  →  추가 납부액
              ↓
    해당 연도 원장에 반영
```

**UI 표시:** 종합과세가 발동한 해에는 결과에 경고를 띄운다.

## 7. 물가 모듈

목표금액 자체는 **세후 명목 기준**으로 다루고 물가를 반영하지 않는다. 대신 **품목 환산가를 병기**해 체감을 전달한다.

```typescript
type FoodItem = {
  id: string;
  name: string;           // '국밥'
  emoji: string;
  basePrice: number;      // 2026-08 기준가
  basePriceDate: string;
};

/** 미래 가격 = 기준가 × (1 + 외식물가상승률)^경과년수 */
function projectPrice(item: FoodItem, targetDate: string, annualRate: number): number;
```

- 지수: 통계청 **외식물가지수** (전체 CPI보다 상승률이 높아 체감에 가깝다)
- 과거 구간은 실제 지수, 미래 구간은 **과거 10년 평균을 기본값**으로 제안하되 슬라이더로 수정 가능
- 기본 품목: 국밥, 김밥, 아메리카노, 지하철 요금 — 배열이라 추가가 쉽다

**표시 예시**

```
15년 뒤 세후 3.0억
지금 국밥 3,000그릇  →  그때 국밥 1,428그릇 (국밥 2.1만원 기준)
```

### 연도별 상세 편집 테이블

납입액과 근로소득을 연도별로 펼쳐 보여주고 **직접 수정**할 수 있게 한다. 수정한 해가 anchor가 되어 **그 이후 전체가 재계산**된다 (§5.4).

```
연차   월 납입액        연 근로소득       비고
──────────────────────────────────────────────
 1     500만원         6,000만원
 2     525만원         6,300만원
 3     551만원         6,615만원
 4   [1,000만원] 📌    6,946만원        대출 상환 완료
 5     1,050만원     [9,000만원] 📌     이직
 6     1,103만원       9,450만원
 ...
15     1,710만원       1억 4,657만원     ← 매도 시점 세율 결정
──────────────────────────────────────────────
📌 = 직접 입력한 기준점   [초기화]
```

**동작 규칙**

- 수정한 셀은 📌로 표시하고 배경을 강조한다
- 수정 즉시 **이후 연도만** 재계산된다 (이전 연도는 불변)
- 📌를 지우면 이전 anchor 기준으로 자동 복귀한다
- 기본은 접힌 상태 — 대부분의 사용자는 상승률만으로 충분하다
- 매도 시점 행(마지막 연차)은 세율을 좌우하므로 항상 강조 표시한다

> **납입액과 연봉의 상승률은 분리되어 있다.** 연봉은 5% 오르는데 납입액은 10% 늘리는 계획이 자연스럽고, 반대로 연봉이 올라도 지출이 늘어 납입액은 그대로일 수 있다. 둘을 묶으면 이 시나리오를 표현할 수 없다.
>
> 단, **연봉은 세금 계산에도 쓰인다** (§6.4). 연봉이 오르면 세율 구간이 올라가 금융소득에 붙는 세금이 늘어난다. 이 연결을 끊으면 장기 시뮬에서 세금을 과소 추정한다.

### 탭 1 · 미래 설계

```
목표금액(세후 명목) [ 3억 ]  ⇄  월 납입액 [ ? ]
        둘 중 하나를 고정하면 나머지가 자동 계산

결과
  월 84만원부터 시작 → 매년 5% 증액 → 15년 뒤 세후 3.0억
  누적 납입 1.82억 / 세전 평가 3.41억 / 총 세금 4,100만원
  🍲 지금 국밥 3,000그릇 → 그때 1,428그릇

  계좌별 기여도 스택 차트
  세금 내역 브레이크다운
```

### 9.2 합성 백필 — 검증된 것만 한다

**합성 대상: 미국 상장 레버리지 ETF만.** 국내 상장 상품은 백필하지 않는다 (§4.3).

```
합성 일별 수익률 = mult × r_index − ((mult − 1) × rate(t) + spread) / 252
```

**골든 테스트 실측 결과** (겹침 구간을 반으로 나눠 전반부로 스프레드를 적합하고 후반부에 적용한 표본 외 검증)

| ETF | backfillSpread | 표본 외 오차 | 변동성 비율 |
|---|---|---|---|
| QQQ | −0.61% | −0.43%p | 1.009 |
| QLD | −0.12% | +0.50%p | 1.011 |
| TQQQ | −0.64% | +2.67%p | 1.025 |
| SSO | 1.69% | +0.21%p | 1.007 |
| SPXL | 2.38% | +0.36%p | 1.014 |

전부 목표(표본 외 CAGR 오차 3% 이내, 변동성 비율 0.9~1.1)를 통과했다. **스프레드는 종목별 캘리브레이션 값을 상수로 고정**하고, CI에서 이 오차를 회귀 테스트로 검증한다.

**나스닥100 총수익지수(`^XNDX`)는 사용할 수 없다** (1행만 반환). QQQ/QLD/TQQQ의 백필은 PR 지수(`^NDX`)로 가격 시계열을 만들고, 배당 기여분은 별도 레이어로 얹지 않는다 — `backfillSpread`가 배당수익률·운용보수·추적오차를 한꺼번에 흡수하며, 그래서 배당수익률이 보수를 넘어서는 QQQ/QLD/TQQQ에서 음수 스프레드가 나온다.

**SCHD는 백필하지 않는다.** 기초지수(Dow Jones U.S. Dividend 100)가 공개 소스에 없다 (`^DJUSDIV`, `^DJDVY` 모두 빈 응답). **2011-10-20 이후만 제공**하고, 그 이전 구간 선택 시 명시적으로 거부한다.

### 9.3 산출물

```
scripts/build-data.ts        (빌드 타임 + Vercel Cron 일 1회)
        ↓
 public/data/{id}.bin      Float32Array — 종목당 약 32KB
 public/data/meta.json     상장일, 보수, 스프레드, 합성 구간, 최종 갱신일
```

**바이너리 포맷을 쓰는 이유:** 1995~2026년은 약 7,900 거래일이다. `Float32Array`면 종목당 31.6KB, JSON 대비 약 1/5이다. 전체 데이터셋이 약 250KB이고 **선택한 종목만 lazy fetch**한다.

**갱신 전략:** 과거 종가는 불변이므로 ISR 페이지 재생성이 아니라 **데이터 파일 갱신**이 맞는 층위다. Vercel Cron이 일 1회 파일을 재생성하고 `cacheLife('days')`로 캐싱한다.

## 11. URL 스키마

```
/plan?p=1000&m=500&mg=5&ma=4:1000&inc=6000&ig=5&ia=5:9000&y=15
      &alloc=ISA:60,DIRECT_US:40&exp=NASDAQ100_2X
      &src=path&from=2011-08&to=2026-08&harvest=1&cur=KRW&target=300000000
```

| 키 | 의미 |
|---|---|
| `p` | 초기 원금 (만원) |
| `m` | 월 납입액 1년차 (만원) |
| `mg` | 납입액 상승률 (%) |
| `ma` | 납입액 anchor — `연차:값` 쉼표 구분 (예: `4:1000,9:1500`) |
| `inc` | **현재** 연봉 총급여 (만원) |
| `ig` | 연봉 상승률 (%) |
| `ia` | 연봉 anchor — 동일 포맷 |
| `base` | 과세표준 직접 입력 (만원, 선택) |
| `y` | 기간 (년) |
| `alloc` | 계좌 배분 |
| `exp` | 지수 노출 |
| `src` | `path` \| `cagr` |
| `from`/`to` | 참조 구간 (src=path) |
| `r` | 연 수익률 (src=cagr) |
| `harvest` | 250만원 공제 소진 전략 (`1` \| `0`) |
| `fx` | 환율 가정 — `fixed` \| `path` \| `drift:2.0` |
| `cur` | 표시 통화 |
| `target` | 목표금액 (역산 모드) |

> 연 근로소득은 민감 정보다. URL에 담기므로 **공유 시 소득이 노출된다는 점을 공유 버튼 옆에 명시**하고, 소득을 뺀 링크를 만드는 옵션을 함께 제공한다.

값이 없으면 기본값을 적용하고, 유효하지 않으면 기본값으로 폴백한다 (에러 화면을 띄우지 않는다). 파싱은 Zod 스키마로 검증한다.

## 12. 테스트 전략

`lib/` 전체가 순수 함수이므로 Vitest로 완전히 커버 가능하다. **TDD로 아래 순서대로 작성한다.**

| # | 대상 | 핵심 케이스 |
|---|---|---|
| 1 | 양도소득세 | 이익 250만원 정확히 = 세금 0 / 250만 1원 = 22원 / 손실 시 0 / 연도별 공제 초기화 |
| 2 | **공제 소진 전략** | 미실현이익 < 250만이면 그만큼만 실현 / 미실현손실이면 실현 안 함 / 취득원가 step-up 누적 / 30년 후 `holdUntilExit` 대비 절세액 검증 |
| 3 | ISA 정산 | 순소득 200만 = 0 / 300만 = (300−200)×9.9% / 손익통산 후 순손실 = 0 / 3년 미만 해지 소급 |
| 4 | ISA 한도 | 연 2,000만 초과 거부 / 미사용분 이월 / 총 1억 도달 |
| 5 | **금융소득종합과세** | 2,000만원 정확히 = 미발동 / 1원 초과 = 발동 / 비교과세 A·B 중 큰 쪽 채택 / ISA·해외양도차익이 합산에서 제외됨 / 근로소득 0원 케이스 |
| 6 | **AnchoredSchedule** | anchor 없으면 `base × (1+g)^t` / anchor 이후는 anchor 기준 재계산 / anchor 이전 연도는 불변 / anchor 여러 개 시 가장 가까운 이전 것 선택 / 0년차 anchor가 base를 덮어씀 / anchor 삭제 시 복귀 |
| 7 | **연도별 근로소득** | 납입액과 **다른 상승률** 적용 / **매 연도 판정** (마지막 해만 계산하지 않음) / 분배금만 있는 해는 미발동, 매도 연도만 발동 |
| 8 | **한 해 몰아팔기 세율 폭발** | 국내ETF 매매차익 3억 일괄 실현 시 실효세율이 15.4%를 크게 상회 / 같은 금액 해외직투는 22% 고정 / 5년 분할 시 절감액 / 역전 금액 산출 |
| 9 | **근로소득공제** | 5개 구간 경계값 / 공제 한도 2,000만원 / 과세표준 직접 입력 시 총급여 무시 |
| 10 | **누진세율** | 8개 구간 경계값에서 누진공제 방식과 구간별 적분 방식이 일치 |
| 11 | 레버리지 모델 | `usListed` vs `krSynthetic`이 환율 변동 시 다른 결과를 낸다 / 1배에서는 교차항만큼만 차이 |
| 12 | 합성 골든 테스트 | QLD·TQQQ·SSO·SPXL 연환산 오차 < 1% — **실측 기준값 고정**: QLD +0.03%, TQQQ −0.33%, SSO −0.12%, SPXL +0.28% |
| 13 | **상장 이전 참조 거부** | 국내 상장 상품 + 상장 이전 참조 구간 = `BEFORE_LISTING` / CAGR 자동 전환 / SCHD 2011-10 이전 거부 |
| 14 | **FxAssumption** | `fixed`는 전 구간 동일 환율 / `path`는 실제 경로 / `drift`는 연 X% 복리 / 탭별 기본값 |
| 15 | 경로 반복 | 3년 구간 → 10년 시뮬 시 인덱스가 정확히 순환 |
| 16 | 역산 수렴 | 이분탐색이 목표금액 ±1원 내 수렴 / 도달 불가능 시 `reachable: false` |
| 17 | 이전 손익분기 | 양도세 즉시 발생 후 역전 시점이 단조 |
| 18 | 상품 매핑 | ISA + NASDAQ100_3X = `available: false` / ISA + SP500_2X = `ONLY_HEDGED_IN_KR` |
| 19 | 매수 시점 | 1일이 휴장이면 다음 거래일 / 연말연시·공휴일 경계 |
| 20 | URL 왕복 | 직렬화 → 파싱 → 동일 입력 복원 / anchor 포맷 파싱 / 소득 제외 링크 생성 |

## 13. 신뢰성 · 투명성 원칙

이 사이트는 사람의 재무 결정에 영향을 준다. 다음을 강제한다.

1. **합성 데이터는 항상 표시한다.** 차트·툴팁·결과 배지 3중으로 노출한다.
2. **불가능한 조합은 대체하지 않는다.** ISA + TQQQ는 조용히 QQQ로 바꾸지 않고 거부한다.
3. **추정치는 추정치라고 쓴다.** 차입비용 스프레드, 국내 상품 총비용, 미래 물가상승률, **근사 과세표준**은 툴팁에 가정을 명시한다.
   - 특히 과세표준은 부양가족·연금·보험료 공제를 반영하지 않아 **실제보다 높게** 나온다. 즉 종합과세 세액이 보수적(과대)으로 추정된다는 점을 밝힌다.
   - 세금 계산은 참고용이며 실제 신고는 세무 전문가와 상의해야 한다는 문구를 세금 카드에 고정한다.
4. **레버리지 리스크를 숨기지 않는다.** 레버리지 노출 선택 시 MDD와 회복 소요기간을 항상 함께 표시한다.
5. **투자 권유가 아님을 명시한다.** 푸터 고정 면책 문구.

| 5 | 최근 조정 전고점 날짜 | 확보한 데이터로 산출 | 프리셋 1개 누락 |
| 6 | **상품별 연 배당수익률** | 발행사·운용사 공시 | 금융소득종합과세 발동 시점이 어긋난다. 가격 시계열(adjClose)에는 이미 반영돼 있어 수익률에는 영향 없음 |

**남은 6개 중 구현을 막는 것은 없다.** 1번은 백필 금지와 미래 시뮬 거부로 우회 중이고, 나머지는 대략 수치 + 툴팁으로 처리하다가 확인되면 상수만 교체하면 된다.

## 15. 향후 확장 (v2+)

`TaxStrategy` 인터페이스와 상품 카탈로그가 확장 포인트다. 아래는 기존 코드를 수정하지 않고 추가 가능하다.

- 연금저축 / IRP 계좌 (`TaxStrategy` 구현체 추가)
- 환헤지 상품 (`Product.hedged = true` + 헤지비용 모델)
- 몬테카를로 분포 (`ReturnSource`에 케이스 추가)
- **분할 매도 최적화** — 국내상장 ETF 매도를 여러 해에 나눠 종합과세 누진을 회피하는 최적 매도 스케줄 탐색 (§6.4의 세율 폭발 문제에 대한 해법)
- 정밀 소득공제 (부양가족·연금저축·보험료·의료비)
- 건강보험료 피부양자 탈락 및 지역가입자 전환 영향
- 서민형 ISA (비과세 400만원)
- 품목 확대 (아파트, 자동차 등)
- OG 이미지 동적 생성으로 공유 시 결과 미리보기
